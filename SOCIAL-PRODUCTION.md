# Social production follows publication

The W45 source audit is in `data/social-production/audits/2026-W45.json`. All 60 original tracked URLs reached their intended article, but the source audit found factual, attribution, geography and photo errors. `source-audit-corrections-2026-11-02.json` repairs the destination articles. `Repair Social Approval Batch` runs after their successful site deployment, requires the exact corrected live article fingerprints, checks all revised links, and preserves the original artifact and approval in history. Revision 2 replaces four selections and two misleading photos. It is a new draft requiring owner approval; the original approval cannot authorize the changed content. The new artifact is emailed once using artifact-specific delivery deduplication. `SOURCE_AUDIT.json` travels with the complete visual review package.

Social selection now checks featured-country evidence independently of upstream discovery labels. Source-checked country records are tied to article content hashes; changed content invalidates them. Future candidates without a reviewed record must have explicit country anchors and still require the full source and visual review. A linked headline without a substantive Brief article cannot be used in a repaired batch. PNAS coverage in this audit is explicitly abstract-only; the full paper was not reviewed.

A successful `deploy` job in **Build and Publish AIEO Brief** calls **Prepare Social Approval Batch** directly. It runs in the same deployment dependency graph, including builds invoked by Follow Observatory Editions. There is no social production cron or extra workflow_run chain.

The producer compares the deployed build's edition with the live public-items dataset. It derives the publication week from the edition's coverage dates, checks a durable completion receipt, then prepares 14 News items across five markets and one Wednesday Research item. Each item has LinkedIn, Facebook, Instagram and Substack copy, one LinkedIn image, three Facebook/Instagram images and three ordered Story frames. The output also includes a weekly Substack Post, source references, rights records, URL/SHA-256 photo checks and live article-link checks.

Download `social-review-RUN-ATTEMPT` from the Actions run and open `BATCH_REVIEW.md`. Paths in the downloaded JSON are relative to the artifact folder. Run the package validator from that folder. `READY_FOR_REVIEW.json` means the technical package checks passed; every item is still `DRAFT_NOT_APPROVED_DO_NOT_PUBLISH`. Editorial review must check copy, featured geography, photo relevance, evidence and topical hashtags. Photographs are illustrative country scenes, not images of the reported events. No paid model is called.

The first recovery edition has curated copy and individually selected public-domain/CC0 photographs in `config/social-2026-W43.json`. Future editions use source-bound draft selection. If a market, current Research item, valid destination, fresh photograph or fitting layout is unavailable, production fails visibly and retains partial diagnostic artifacts. It never silently fills a missing market or reuses a photo. Production can be retried with the workflow's manual Run action after the blocker is fixed.

Only after the completed artifact is uploaded does the workflow record its URL in `data/social-production/state.json` and append photograph identities to `config/social-photo-history.json`, using the existing repository-scoped publisher action. Later culture updates and repeat deployments skip an already-produced news edition. Draft receipts are committed with `[skip ci]`; neither draft assets nor captions are deployed to the public website.

For every Facebook or Instagram carousel, use the numbered files in `prepared_carousel_assets` as 1 cover/photo and headline, 2 explanation, 3 CTA. Add one file at a time in Meta Business Suite and wait until it has finished processing before adding the next; selecting all three at once can save them in completion order rather than selection order. After the post is saved, reopen it and inspect all three cards in the saved preview (or the live Instagram post). Record `saved_media_order: ["cover", "explanation", "cta"]`, `saved_order_checked_after_save: true`, and `saved_order_evidence` as three distinct screenshot paths in card order in the publication audit. A composer preview or the prepared filenames alone does not certify platform order. Run `python scripts/validate_social_package.py batch.json --audit PUBLISH_AUDIT.json` before declaring the queue verified. If a saved scheduled copy is wrong, create and verify its replacement at the intended time before moving the wrong copy to Drafts. If a live copy is wrong, publish and verify its replacement before retiring the wrong one.

This workflow has no social platform credentials and cannot post or schedule. The user reviews the complete package and explicitly approves `APPROVE SOCIAL WEEK YYYY-WW`. The existing publishing chat then publishes overdue approved slots and schedules future approved slots, checking each saved placement. The chat heartbeat is a notification/recovery bridge and is no longer the trigger for production. GitHub does not directly wake a local Codex chat; local notification checks require the app to be running.

**Email delivery:** After a successful website build or manually prepared social batch, **Email Social Approval Batch** retrieves the current Amsterdam publication week's completed artifact and emails the confirmed owner using the existing `RESEND_API_KEY`, `RESEND_FROM_EMAIL`, and `WEEKLY_REVIEW_TO_EMAIL` secrets. The email contains the schedule and full-media download link, plus attached `BATCH_REVIEW.html` (all platform captions, carousel and Story previews, source links and photo credits) and `BATCH_REVIEW.md`. Media previews are smaller copies; the artifact retains full-resolution originals. Delivery requests review only and cannot approve or publish. A provider acceptance receipt in `data/social-production/email-receipts.json` prevents repeat emails on later deployments; a stable provider idempotency key covers immediate retries. Failed or incomplete batches are never represented as ready. The workflow can be run manually to recover a missed email without regenerating assets, and installing the delivery workflow sends the existing current-week batch. Delivery runs on GitHub and does not require the local app to be open.

**Combined post previews and repository approval:** The email itself includes a complete Facebook feed preview for every selection, with account, exact caption and all carousel cards together. The attached HTML includes all 60 platform placements and all Story frames, with the actual prepared copy and images together. Expanded carousel cards preserve order for review; platform controls, cropping and line wrapping can vary. The identical standalone HTML, Markdown, batch identity and digest are retained as `social-visual-review-RUN` in the email workflow run. The email's approval/correction link opens this run, which waits for the same protected `weekly-editorial` owner review used by the authored News / Research weekly summary. Approval saves `data/social-production/approved/YYYY-Www.json` only after verifying the owner's GitHub account, environment review, exact batch digest and unchanged source artifact. It does not itself post to social accounts. A Monday 12:30 UTC recovery check retries missed deliveries without regenerating or repeatedly emailing a completed review. Review format upgrades can send one updated visual review for the same week, with a distinct provider idempotency key.
