# Social production follows publication

A successful `deploy` job in **Build and Publish AIEO Brief** calls **Prepare Social Approval Batch** directly. It runs in the same deployment dependency graph, including builds invoked by Follow Observatory Editions. There is no social production cron or extra workflow_run chain.

The producer compares the deployed build's edition with the live public-items dataset. It derives the publication week from the edition's coverage dates, checks a durable completion receipt, then prepares 14 News items across five markets and one Wednesday Research item. Each item has LinkedIn, Facebook, Instagram and Substack copy, one LinkedIn image, three Facebook/Instagram images and three ordered Story frames. The output also includes a weekly Substack Post, source references, rights records, URL/SHA-256 photo checks and live article-link checks.

Download `social-review-RUN-ATTEMPT` from the Actions run and open `BATCH_REVIEW.md`. Paths in the downloaded JSON are relative to the artifact folder. Run the package validator from that folder. `READY_FOR_REVIEW.json` means the technical package checks passed; every item is still `DRAFT_NOT_APPROVED_DO_NOT_PUBLISH`. Editorial review must check copy, featured geography, photo relevance, evidence and topical hashtags. Photographs are illustrative country scenes, not images of the reported events. No paid model is called.

The first recovery edition has curated copy and individually selected public-domain/CC0 photographs in `config/social-2026-W43.json`. Future editions use source-bound draft selection. If a market, current Research item, valid destination, fresh photograph or fitting layout is unavailable, production fails visibly and retains partial diagnostic artifacts. It never silently fills a missing market or reuses a photo. Production can be retried with the workflow's manual Run action after the blocker is fixed.

Only after the completed artifact is uploaded does the workflow record its URL in `data/social-production/state.json` and append photograph identities to `config/social-photo-history.json`, using the existing repository-scoped publisher action. Later culture updates and repeat deployments skip an already-produced news edition. Draft receipts are committed with `[skip ci]`; neither draft assets nor captions are deployed to the public website.

This workflow has no social platform credentials and cannot post or schedule. The user reviews the complete package and explicitly approves `APPROVE SOCIAL WEEK YYYY-WW`. The existing publishing chat then publishes overdue approved slots and schedules future approved slots, checking each saved placement. The chat heartbeat is a notification/recovery bridge and is no longer the trigger for production. GitHub does not directly wake a local Codex chat; local notification checks require the app to be running.
